# Service source

Forked from clash-verge-service-ipc v2.7.6, GPL-3.0; see LICENSE. Suki uses its own service names, directories and protocol endpoints. It never adopts or removes the CV service. Legacy owner-file cleanup and old macOS helper uninstallation are removed. The application owns OS proxy intent and recovery. On macOS, the authenticated active service session executes the restricted proxy transaction engine and native adapter; it does not accept arbitrary commands or clear unrelated OS proxy settings. Current protocol revisions must match exactly; no old owner-format or service adoption is supported. Core watchdog retries are limited to three.

Revision 6 adds authenticated Windows network operations, following the ClashSuki native AppContainer approach. The helper accepts only known AppContainer identities and a fixed firewall operation for its approved core and the authenticated owner's application-local core. It never accepts arbitrary command lines or firewall program paths.

Revision 8 added session-scoped, bounded core-log history with a helper-start identity and monotonic cursor. The app and helper must be published together; older protocol revisions are rejected explicitly.

Current protocol revision 9 adds authenticated readback for a fixed Geo database allowlist, adapted from the CV dev update to service v2.7.7. Provider and Geo reads retain private-generation path restrictions; arbitrary copied assets and SSH key assets are not exposed. The app streams newer Geo data before local validation and after core Geo updates. SSH file-key staging is handled by the app runtime bundle. Suki maintains its own package version independently of the upstream fork version and protocol identity. App and helper must ship together; no older-protocol fallback is provided.

Since 2026-11-05, Suki ships one service executable with integrated installation and removal commands, following the command dispatch pattern in ClashSuki.Service. No separate install/uninstall executables or NSIS service installer are built or packaged. Maintenance is dispatched before daemon logging, ownership or runtime startup. The application stages the same service executable for elevation and verifies the existing installation contract; this changes delivery and local CLI dispatch, not IPC revision 9. See [implementation record](../docs/features/network/tun-service.md).

Since 2026-11-11, both IPC ends use Hyper over local named pipes or Unix sockets; kode-bridge is removed. Connections carry one request each, retain the existing authentication and protocol, and are owned and joined by the listener task during shutdown. HTTP headers, bodies, connection count and execution time are bounded. Service logging uses tracing-subscriber and flexi_logger directly, without tracing-estuary.

The Cargo library shares protocol, client and platform code with the application. Only the `suki-clash-service` binary is shipped. `mock_binary` and `service-integration-driver` support subprocess integration checks selected through Cargo features. The unused `crash_binary` and `owner_lock_holder` fixtures have been removed.

`client` enables local IPC and platform service queries; `standalone` adds the daemon, PAC URL validation and executable resources. Platform dependencies use their actual crate names (`libc` and `windows-service`). `serial_test` serializes tests that share isolated service state, and `tempfile` provides temporary test directories; both are development dependencies. The `test` feature selects isolated endpoints and fixture credentials for subprocess integration tests, independently of Rust's `cfg(test)`.

Windows firewall cleanup uses empty `core-firewall-rules/<core-name>.record` markers. These are cleanup obligations, not executable copies. Only this record format is read; existing installations are not migrated. The executable approved for privileged execution remains in `cores`.
