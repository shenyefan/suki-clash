## CV 行为核对

- `core/manager/lifecycle.rs::wait_for_service_if_needed` 对 Windows 未提权且请求 TUN 的冷启动等待服务；`constants.rs` 定义最多 30 秒、200 ms 间隔。
- `core/runstate/mod.rs::await_ready` 只重试未获得响应的传输失败；服务回复明确拒绝或协议不符时结束等待。不可连接不等于未安装。
- `core/manager/state.rs` 从子进程启动时持续读取标准输出／错误输出，避免启动日志缺失和管道阻塞。

## 本项目处理

- 启动就绪使用同一总等待窗口确认 API、监听配置和 TUN；TUN 启动最多等待 30 秒，不再被内部 3 秒校验提前终止。设置／订阅热更新及其恢复也使用统一配置就绪等待。
- Windows 请求 TUN 且未提权时，服务冷启动提供有界等待；安装／修复后同样等待服务就绪。只重试尚未可连接的探测，服务拒绝、协议不符、权限及格式错误立即结束。
- 服务客户端使用 Hyper 处理私有 HTTP，Unix Socket／Windows Named Pipe 保留原始权限错误及 Windows 注册服务进程身份核验。删除底层自动重试和逐次连接警告，由工作流决定等待；即使拒绝响应的正文中断或超时，也保留已读到的 HTTP 拒绝状态。
- 服务客户端在共享边界保留连接、HTTP 拒绝、业务拒绝、协议、权限和响应格式的区别；启动、状态、日志、运行资源、安装检查、系统代理和 Windows 网络操作沿用同一分类。日志拒绝不连续重连，所有者检查不把明确拒绝当作不存在可用服务，提权直启也不吞掉服务拒绝。启动探测遇到明确拒绝直接结束；运行状态恢复仅对暂时无法连接继续观察。安装器的等待和 ensure 检查、集成驱动同样不吞掉拒绝。服务所有权健康检查遇到明确拒绝直接报错，不据此终止原服务或进入接管。
- 服务进程创建后即持续读取带归属的日志窗口，日志采集独立于运行数据的就绪门槛，复用日志级别解析、脱敏与文件记录；失败时返回本次启动已采集的内核错误，保留独立的清理失败。
- 后台订阅定时器和系统代理回读保留原失败原因及其日志标记。内核页可重新查看原因，仍使用错误 toast。
- 常规服务 IPC 请求仅记录 TRACE，删除不准确的“使用内核配置”；底层连接失败直接传播，由上层操作报告。
