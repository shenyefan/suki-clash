# 托盘、诊断与操作日志复核（2026-11-05）

本批延续用户报告的 Windows 问题，并按新决定记录操作及完整原始错误，Toast 文案和交互保持原样。代码共用的日志、诊断和标题控件适用于三平台；平台能力仍由各自执行端负责。

## 已修复的调用链

| 范围 | 原因与处理 |
| --- | --- |
| Windows 托盘一闪而过 | `tray-icon 0.26.1` 的 Windows 实现先发送鼠标 Up 事件，再进入 `TrackPopupMenu`。应用原来在该事件里清空菜单版本并重新 `set_menu`，可能销毁正在跟踪的菜单句柄。现移除点击中的菜单重建，菜单按实际状态版本更新。默认打开菜单交给 OS；其他左键动作继续提交真实命令。 |
| macOS／Linux 托盘 | macOS 使用原生 AppKit 附着菜单，Linux 使用 ksni StatusNotifier／DBusMenu；共同点击路径均不重建菜单。Linux 并非 GTK 托盘实现。原生菜单视觉、系统栏扩展及交互仍需实机验证。 |
| “选择应用尚未接入实际执行逻辑” | 设置字段按钮经过 `local_action`，原有 UWP 处理放在另一条未到达的分支。现把按钮接到已有 UWP 工作流，读取应用和提交回环修改仍经类型化命令；非 Windows 返回实际能力限制。 |
| 系统代理／虚拟网卡开关 | 开关紧邻标题，TUN 正文不再重复显示。继续使用实际状态，拒绝操作时不保留失败开关值；手动／PAC 分段控件保留在右侧。 |

参考当前本地 CV `src-tauri/src/core/tray/mod.rs::on_tray_icon_event`：`TrayMenu` 分支不另行处理，由原生附着菜单展示；菜单刷新属于状态更新链。实现没有复制 Tauri 的全局状态或命令机制。

## 日志与导出

- 生命周期执行端记录请求开始、操作、内核代次、配置修订及结束／失败／已提交事实；设置仅记录字段名，不记录值。测速批次、定时订阅／覆写更新、出口 IP 刷新、退出／重启／重置／应用更新及存储操作也记录生命周期。
- 原本只返回固定提示的 I/O、进程、解析、系统代理及其他边界同时记录原始错误；HTTP、私有 HTTP／WebSocket 和服务请求保留可用原因链，Windows 凭据失败保留系统错误码。界面直接拒绝和 panic 也进入日志；不增加额外 Toast。
- 程序与自有服务客户端的 `log` 记录复用已有后台写入线程。第三方日志不整体导入；写入队列不可用或日志存储故障时保留有界内存诊断，避免日志错误递归进入同一个写入队列。
- 去掉程序错误 8192 字符截断，长记录按 UTF-8 边界分段写入，保留尾部原因。现有日志级别、轮转与容量策略继续生效，凭据和来源 URL 继续脱敏，不导出配置正文。
- 程序日志默认清理周期为 7 天；用户明确保存的其他策略继续生效，不迁移设置。清理跳过当前正在写入的文件。
- 诊断 ZIP 新增 `logs/program-current.log`、`logs/core-current.log`，以及本次运行登记的磁盘日志与轮转分段，包括内核重启后新建的日志。不是用文件修改时间猜测所属运行；不混入之前应用运行的文件。内存尾部每种来源最多 1000 条，磁盘日志总上限 64 MiB，缺失、读取失败及截断写入 `logs/export-status.txt`。机器级服务自身的日志仍由服务独立持有，不等同于应用采集的内核日志。

## 用户提供日志的解释

| 日志 | 判断 |
| --- | --- |
| 内核已就绪、订阅已保存、节点已切换 | 各自阶段的正常完成；内核 API 就绪不能证明出口节点和检测目标连通。 |
| 选择应用尚未接入实际执行逻辑 | 应用按钮分发错误，已接回已有 UWP 工作流。 |
| 后台服务未就绪 | 当次操作未取得可用后台服务；需要结合安装／启动请求判断。后面的“内核已就绪”不能消除这次失败事实。 |
| 内核已安装，但防火墙规则配置未完成 | 安装已经提交，防火墙步骤未完成；不能把它报告为整体安装失败。 |
| 出口请求、出口 IP 检测：HTTP 连接失败 | 检测经代理出口建立 HTTP 连接失败；旧日志缺少下层原因，无法仅凭该行区分节点、网络、TLS 或目标服务。新日志保留原始错误链供定位。 |
| 0x800706D9 | `EPT_S_NOT_REGISTERED`，表示没有可用 RPC 端点。结合防火墙步骤，需检查 Windows Defender Firewall（MpsSvc）、Base Filtering Engine（BFE）、RPC 及端点映射相关服务；没有机器状态不能断言具体哪个服务停止。诊断写入日志，返回错误和 Toast 保持原样，不自动修改系统服务。 |

微软说明此错误可能出现在防火墙服务不可用的场景：[Windows 更新故障排查](https://learn.microsoft.com/en-us/troubleshoot/windows-client/installing-updates-features-roles/windows-update-issues-troubleshooting)、[RDS 安装与防火墙服务](https://learn.microsoft.com/en-us/troubleshoot/windows-server/remote/rds-role-fail-to-install)。这是排查方向，不是该用户机器已经确认的根因。
