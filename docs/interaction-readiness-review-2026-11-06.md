# 节点选择、设置进入与本地通道就绪复核

## 发现与修复

| 场景 | 原因 | 调整 |
| --- | --- | --- |
| 选择节点后所有代理组选中状态闪动 | 选择前后均递增监测修订并清空目标，统计、代理、日志和测速监督重新开始 | 选择及取消固定不改变配置身份，原数据和连接保留；命令结束后通知采集端刷新已确认选择。模式切换也不重建监测 |
| 进入设置后短暂无法编辑 | 自启动状态查询与配置修改共用排他命令通道，提交查询立即使所有设置进入禁用态 | 自启动查询由执行端持有独立阻塞任务，查询不占修改通道；结果绑定发起时的命令身份，避免覆盖期间发生的新设置 |
| 重开设置页有额外停顿 | 不论值是否变化都重新设置输入值、主题和原生窗口材质 | 相同值不重置输入和选择；外观同步仅处理实际变化或失败后的草稿恢复。外部资源在同一内核代次不重复请求 |
| 缺少服务时启用 TUN 只报错 | 标题栏、托盘和表单没有统一的恢复目的地 | GPUI 桥接层识别启用意图，缺少／无法连接服务时发出语义事件；应用显示虚拟网卡页并提示安装或修复，开关及设置保持原值。执行端发现服务失效时也提供相同恢复事件 |
| TUN 切换期间本地通道暂不可用 | IPC 建立失败立即报告，部分启动探测的临时错误也由低层直接记录 | Unix Socket／Windows Named Pipe 建立前对不存在、拒绝连接、连接中止及管道忙进行最多 3 秒的等待，间隔 100 ms；错误由调用方在实际失败后报告，不逐次记录 Error |
| 日志包含内部编号 | 命令开始、完成、失败和测速日志插入请求编号 | 移除正文中的请求编号，内部身份仍用于去重、结果关联及拒绝过期结果 |

连接等待仅发生在发送 HTTP 请求之前；已发送操作没有自动重发，避免应答丢失后重复修改。读取及实际配置确认继续使用既有有界就绪流程。标题栏与托盘在内核操作期间禁用状态操作，正常监测只在内核实际配置就绪后启动。

## 参考边界

- 本地 CV `src/hooks/use-proxy-selection.ts` 对指定代理组选择，随后同步选择和托盘，不重建所有实时连接。
- CV `src-tauri/src/core/manager/state.rs` 对就绪探测使用有界重试，中间失败记录 Debug。
- CV `src-tauri/src/feat/tun.rs` 包含服务缺失时自动关闭 TUN 的产品策略；Suki 按用户要求显示服务管理页，不自动修改用户设置或自动安装服务。
- 跨功能导航通过 GPUI 语义事件交给应用壳处理；内核领域执行端不依赖应用页面或焦点。

## 验证范围

- 内核相关测试：114 通过，16 项需要显式真实内核／运行包的测试未执行。新增检查延迟建立通道、丢失应答后不重发、选择期间监测目标稳定、自启动查询不阻塞修改通道，以及标题栏／托盘／表单三个缺少服务入口。
- 设置测试：19 通过，覆盖重开不禁用控件、不重新应用材质及既有失败草稿恢复。
- 代理组相关测试：36 通过，包含虚拟列表、展开、定位、筛选及测速顺序。
- 应用相关测试：8 通过，覆盖全部导航目的地、标题栏、侧栏及初始化失败保留完整界面。格式检查及严格 Clippy 通过。
- macOS 原生窗口：使用独立临时设置与不可用内核适配器，确认打开设置后可直接在启动脚本输入框输入。未启动内核、安装服务或改变系统网络；临时进程和构建入口已清理。
- Windows／Linux 原生托盘及真实 TUN 驱动未实机验证；不将上述隔离测试视作平台网络验收。
