# CV 对照修复清单

更新：2026-11-03。依据 [源码复核报告](cv-parity-review-2026-10-31.md)、[功能差距清单](cv-gap-checklist.md) 和 [逐文件台账](cv-file-review.md)。本清单将报告转为实施任务，不代表已修复或重新验证。证据路径、触发条件与参考版本沿用报告；实施前复核当前源码，避免依据过期行号修改。

覆盖61项代码问题R01–R61、5项生命周期问题L01–L05、1组入口／授权问题S01。每项保留原编号，合并实施时也逐项关闭。另列报告补充项、待确认项和缺功能，不把它们混入61项计数。

## 实施规则与顺序

- 复选框记录代码修复完成；自动检查和真实平台验收分别记录，勾选不代表实机验收。只编译通过不得勾选平台行为完成。
- 先修服务启动阻断、归属与退出，再修补偿／资产／系统代理，随后修数据完整性、来源与测速，最后处理界面一致性。
- 参考CV完整执行链，但保留明确的产品决定和已有改进。不加入自动换端口、默认配置兜底、旧格式兼容／迁移、按订阅DNS、侧边跳转等已排除行为。
- 不为清空清单自行扩大产品范围。缺执行消费者的设置先核对授权；已要求保留的同步入口不得顺手删除。
- 每次修复明确提交点：设置、文件、内核、系统网络分别报告。原始失败、已提交事实、独立恢复失败不能互相覆盖；重试有界，权限拒绝后停止自动写入。
- 退出只清理本应用拥有的内核与网络效果；已安装helper可以空闲常驻。AutoRun只控制应用登录启动，不控制helper系统注册。

优先级：P0为阻断；P1为服务、网络、恢复或数据完整性；P2为行为一致性和诊断；P3为局部展示。下列优先级是实施排序，不改变报告原始严重程度。
