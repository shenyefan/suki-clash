# 日志

内核与程序分别保存到应用数据目录的 `logs/`，文件前缀为 `core-` 和 `program-`。

- 内核页：内核日志级别、文件大小、保留天数。级别应用到 Mihomo；运行与校验进程的输出均记录。
- 设置页：程序日志级别（默认 Info）、单文件 KB、文件数量及清理周期。设置即时保存并应用，程序设置不影响内核日志。
- Error：操作失败及日志保存失败；Warning：可恢复异常或未支持的操作；Info：生命周期与业务结果；Debug：常规保存、目录及文件操作；Trace：细粒度诊断。所选级别包含更严重级别，Silent 停止常规程序日志。
- 来源显示内核消息的 `[TCP]`、`[DNS]` 等前缀，未标记的输出显示 `mihomo`；程序显示 `core`、`settings`、`profiles`、`overrides`、`storage` 等模块。
- 后台按来源保留最近 1000 条实时记录，界面每 150 ms 批量读取。文件保留独立于界面缓冲和清空操作。
- 默认按时间倒序，时间相同时按记录序号排序。来源、排序、筛选和搜索不保存到设置文件。
- 内核凭据在发布和保存前统一脱敏。过长日志整行丢弃并记录警告，跳过后续片段，直到换行恢复。
- 程序日志由独立日志线程写文件，队列容量 4096；超过 75% 仅接收 WARNING 及以上，满则丢弃并记录丢弃数。低于所选级别的日志不进入内存和文件，设置保存后立即生效。
- 文件写入失败只报告一次，记录暂存于内存，每 5 秒重试，恢复后补写缺口数量；内核管道继续读取，避免堵塞子进程。

自动化验证覆盖日志解析、分级筛选、分卷及文件数量、设置热更新、脱敏、过长行、来源隔离、默认排序、详情宽度和不保存浏览状态。原生窗口的手动验收另行记录。

程序错误由产生边界直接传播，批量和并行任务合并相同原因；不重复模块前缀或逐层添加失败文案。测速正常完成与图标缓存就绪记录 Debug，批次失败记录 Warning。实时刷新恢复选中身份不触发定位，保留用户滚动位置。

日志级别、文案规范、重复归属及已知问题见 [logging-audit.md](../../reviews/logging/logging-audit.md)。

脚本执行日志保存在 `logs/overrides/*.json`，按程序日志的保留天数与文件数量统一清理。

## 操作记录与诊断导出

生命周期、测速批次、定时更新、出口探测、存储及退出操作记录开始、结果与独立恢复失败。设置只记录字段名，不记录值；正文不包含内部请求编号，身份仍用于结果关联和去重。同一次命令错误由执行端记录一次，界面显示一次错误 toast；启动错误与独立资源警告分别报告。

程序错误保留原始原因链，不截断为固定提示；长记录按 UTF-8 边界分段，凭据与来源 URL 脱敏。程序及自有服务客户端日志复用后台写入线程，第三方日志不整体导入。队列或磁盘故障保留有界内存诊断，避免递归写入失败队列。程序日志默认清理周期为 7 天，跳过当前写入文件，保留用户显式设置。

诊断日志只包含本次运行登记的磁盘文件及轮转分段，包含内核重启后新建文件；不根据修改时间混入历史运行。内存每种来源最多 1000 条，磁盘日志总上限 64 MiB。读取失败、缺失和截断集中记录到 `environment.txt`；机器级服务自身日志与应用采集的内核日志分别持有。配置副本、脱敏及环境信息范围见 [诊断与托盘](diagnostics-tray.md)。
