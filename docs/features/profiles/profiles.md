# 订阅

状态更新（2026-11-09）：用户确认文档此前列出的实机验收部分均已完成，相关待验收项关闭。下文各次检查中的“未验收／待验收”保留为当时记录；本次未重新运行验收。实现范围、暂缓项及能力限制以[当前功能对照](../../reference/cv/cv-gap-checklist.md)为准。

参考本地 CV 的导入、更新、序列增强、活动删除和定时更新行为，使用本项目的生命周期执行端和配置工作流。

## 已接入

- HTTP/HTTPS 链接导入、本地文件导入、文件拖放及新建 YAML。页面有链接时直接下载，没有链接时打开信息表单；设置图标主动打开与编辑信息共用的表单，地址同步。
- 单项、所选和全部远程订阅更新；本地订阅不执行网络更新。
- User-Agent、Authorization、下载超时、Age X25519 私钥解密。
- `Content-Disposition` 名称（缺失时取链接文件名或站点名，保留用户自定义名称）、`subscription-userinfo` 流量与到期信息、`profile-update-interval` 小时间隔、`profile-web-page-url` 主页及最后更新时间。
- 名称、地址、正文、更新间隔及自动更新设置；列表排序、单项和批量删除、撤销、复制链接、二维码及打开源文件。
- 订阅激活、活动来源编辑或更新后的热加载；停机时编辑只保存，不启动内核。
- 规则、代理及代理组的 prepend / append / delete 增强。增强单独保存，下载的原始正文不改写。代理删除同步清理组引用，新增代理加入首个选择组，名称去重。
- 删除活动订阅时选择剩余列表的第一项；没有剩余订阅时使用基础来源。运行中先确认新配置生效再提交列表和选择，停机时只更新选择。
- 新导入仅未指定间隔时采用响应头提示，无提示时使用1440分钟；明确填写的1440或0保留。间隔为 0 关闭自动更新，大于 0 自动更新，不保存独立开关。按最后成功下载时间与间隔安排自动更新；首次无更新时间从当前会话开始计时。每 30 秒检查一次。失败按间隔重试，关闭自动更新后不再调度。

## 用户要求的界面变更（2026-10-30）

按用户明确要求，订阅三点菜单不再提供“查看详情”及其专用弹窗；“编辑规则”“编辑代理”“编辑代理组”合并为一个“订阅增强”入口，在同一个弹窗内切换三类内容。弹窗内 YAML／表单编辑切换位于左下角，取消、保存等确认动作位于右下角并使用正常按钮宽度。该位置调整仅作用于弹窗，页面编辑模式按钮保持原位置。

## 下载与凭据

逐订阅选择内核代理、系统代理或直连，内核代理与系统代理互斥；不因下载失败切换传输策略。全局「订阅下载代理」作为新订阅默认值；内核或代理端口不可用时明确报错。系统代理解析由库处理，PAC 脚本解释未实现；Windows/Linux 尚未实机验收。

请求地址、Authorization 和代理认证通过 reqwest 类型化 API 提交；没有外部下载进程。限制重定向次数、协议、超时、正文和响应头大小，拒绝 URL 用户信息。每次先下载到私有临时目录，再解析、解密并校验。解析、文件提交和运行配置应用失败不切换下载策略；取消不重试。

macOS钥匙串、Windows Credential Manager、Linux Secret Service分别提供凭据存储；索引不包含Authorization或Age私钥。两项编辑各自明确保留／替换／清除，空输入保留另一项；清除已保存凭据先改草稿并可撤销，保存才提交。删除已提交后凭据清理失败仍同步列表并保留撤销，同时报告清理错误。测试使用按隔离目录区分的内存存储，不访问真实凭据。

## 状态与提交

`core::Actor` 串行处理订阅修改、更新、定时任务和内核操作。界面提交完整候选列表及基于当前索引的预期版本，过期编辑被拒绝。来源 ID、下载正文、实际激活状态、界面编辑草稿分别维护。

活动来源变化经过合成、目标内核校验、热加载和端口回读，随后提交正文文件、索引、选择记录及私有运行文件。失败恢复旧运行配置和已捕获的文件。恢复失败与原始错误同时报告。更新批次逐项提交，失败项目保留旧内容，已成功项目保留成功结果。

元数据在程序设置 `settings/settings.json` 的 `profiles.items`，正文唯一存于 `profiles/<id>.yaml`，覆写唯一存于 `overrides/<id>.<ext>`，索引不含正文；外部文件修改进入下次读取／合成，元数据保存不重写未修改正文。内存快照含正文用于版本比较，磁盘不双读回退。增强在 `indexes/profile-enhance-<id>.json`。`settings/settings.json` 的 `profiles.selected_profile_id` 字段只保存选中的订阅 ID。不生成 `applied.json`，不读取其他版本的格式。

所有下载在同一个持续 toast 中显示进度，持续到解析、应用和提交结束。toast 使用原生 NotificationList，并在弹窗上层绘制；位置默认「顶部居中」，可在设置中更改。

## 验证

自动化测试覆盖导入、元数据、无效响应保留旧内容、Age 解密、请求头与敏感参数、过期编辑、文件删除、自动更新间隔、序列增强和 toast 弹窗层级。真实 Mihomo 测试覆盖活动编辑、增强、PID 保持、校验失败保留旧来源、活动删除和最后一项删除。

本轮隔离macOS原生窗口确认订阅信息表单、凭据清除／撤销草稿、内容滚动和末尾开关；Windows/Linux、真实钥匙串授权、PAC及完整窗口矩阵仍待验收。覆写脚本执行、远程更新和热应用已单独接入，见 [flow.md](../configuration/flow.md)；不以订阅测试替代覆写执行验收。

首次导入选择第一份订阅为当前来源；后续导入不抢选。URI携带的明确name保留，仅空名称自动获取。远程节点订阅需包含proxies或proxy-providers，空对象／错误映射不可替换有效订阅；合法覆写及本地规则配置按各自边界处理。
