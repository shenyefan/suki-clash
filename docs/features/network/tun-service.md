## 执行与权限

虚拟网卡页的“安装服务”“修复服务”调用随包 `suki-clash-service` 的集成维护入口，申请一次系统管理员授权，登记系统服务并发布管理员批准的 Mihomo 副本。macOS 使用 launchd，Windows 使用 SCM，Linux 使用 systemd。服务待机时保持安装；停止服务内核不卸载服务。

正常启动优先使用已就绪服务，安装／修复后重新选择服务归属；显式转子进程仍是独立操作。普通用户使用已安装服务；应用已具备 root／管理员权限且服务不可用时，可直接运行内核，不重复申请权限。与 CV 一样不提供 Linux setcap 自动授权流程。无论哪种方式都受执行排他锁约束。

已安装服务后，开启 TUN 将普通子进程受控切换到服务内核；关闭 TUN 热更新同一个服务内核，服务继续待机。日常开关不调用提权工具。网卡创建、自动路由、DNS 劫持及退出时释放由 Mihomo 在服务权限下执行；应用不另建一套手写路由。

TUN 参数唯一持久化来源是 `settings/mihomo.yaml` 的 `tun` 对象；程序 JSON 不保存第二份 TUN 参数。保留未知内核字段，按 CV 补齐 fake-ip DNS 所需字段。停止时保存不启动内核；运行时校验、应用、API 回读确认后提交设置，界面开关反映实际回读。

## 所有权与错误

应用生命周期执行端持有服务会话证明，服务验证 OS 调用身份、当前协议、owner token／generation、管理员批准的内核及运行资产路径。普通进程与服务共享执行排他锁。相同启动 token 重复请求返回相同代次，不重复启动；错误 token 不能停止当前内核。

服务不可用且应用也无既有提权权限、协议不符或权限不足时，保留设置和错误原因，不静默关闭 TUN，也不自动启动无权限的第二个内核。安装／修复先停止本应用所有的内核，完成或取消后尝试恢复；失败保留原始失败和独立恢复失败。更新服务内核必须经服务程序的集成安装入口重新批准可执行文件；日常配置不重新批准。

配置热更新通过受保护目录暂存后加载，失败恢复原配置。仅服务返回结构化 RestartRequired 时，使用已校验候选进行受控重启；确认新内核就绪才提交，失败恢复旧内核。其他热更新错误不自动重启。Provider文件通过鉴权分块读取回应用缓存，核对加载时间、2秒稳定窗口、各块及最终EOF身份、当前服务归属和大小上限。启动／配置修订／Provider更新由生命周期执行端触发，每轮最多4次观察、未就绪间隔15秒，真实错误立即停止。Local路径只写来源证明，不改内核缓存mtime；HTTP链物化需URL／内容哈希证明，首次无已确认缓存时明确拒绝，先普通启动同步再启用链，不用未知旧缓存替代。同步确认后通过同一候选配置流重绑来源节点。

macOS服务会话通过鉴权代理命令执行系统代理读写、回滚和清理；应用与helper共用原生适配器及事务引擎，PAC服务和守卫仍由应用Controller持有，不另起第二个代理所有者。代理清理确认和内核停止确认后才解绑会话，失败保留原路由且不回退GUI写入。内核状态确认失败后最多追加15次同归属健康观察，恢复时回读API／TUN并同步代理，耗尽后暂停；服务内核崩溃与 IPC 重建各有最多三次的窗口内恢复预算。systemd 限制启动频率，Windows 恢复动作末尾停止重启；macOS 对已耗尽预算的受控退出不自动拉起，异常崩溃拉起有节流。服务启动恢复失败保留运行意图和损坏文件，不自动改写为关闭。错误只 toast，主界面和草稿保留。

## 构建与交付

运行 `packaging/build-service.sh OUTPUT_DIRECTORY [TARGET]` 只构建并复制 `suki-clash-service`（Windows 加 `.exe`），放在主程序可执行文件同级。macOS 放在 `.app/Contents/MacOS`，按正式签名／公证流程签名。服务程序无参数时运行 daemon，`--install`／`--uninstall` 执行受限平台维护；应用负责调用、暂存、提权及结果确认，不再交付独立安装／卸载程序。脚本只构建和复制，不安装服务。开发时仅 `cargo run` 不会自动构建服务，缺失时界面明确报错。服务维护命令见下文。

## 验证边界

普通测试隔离真实系统服务、系统代理、路由与网卡。已验证原生 TUN 参数的单一来源、类型错误、未知字段保留、CV DNS 补齐行为；独立测试服务与模拟内核验证真实 IPC 的启动、重复确认去重、错误会话拒绝、运行暂存、停止和归属回读。

真实管理员安装、真实 TUN 流量／DNS／路由释放、系统重启及 Windows/Linux 桌面仍需平台实机验收。交叉编译不等同于这些验收，不能据此宣称完整平台验证。

历史阶段构建检查（非整合入口后的复验）：macOS 严格 Clippy；Windows x86_64 GNU 与 Linux aarch64 的服务和当时独立安装／卸载工具交叉编译通过。macOS 隔离窗口确认 TUN 原生控件、缺内核时禁用开关、服务未连接状态及安装／修复动作布局，未点击提权安装。

服务管理已提供卸载及显式转为子进程，动作确认包含关闭 TUN，并提供 5 秒撤销窗口。Windows UWP／防火墙操作使用原生 API 和服务鉴权，见差距清单 C05。当前协议 revision 9，服务协议不符时由用户显式修复，不自动兼容旧协议。

第一批退出修复：交互退出先异步清理并等待存储队列屏障，失败保留执行端和重试入口；最终成功才销毁任务。系统不可取消结束是平台例外，在GPUI同步结束回调中对现有清理线程最多等待3秒，避免其返回future仅有200ms预算；不在该回调中创建新运行时或重复实现清理业务。真实注销／关机仍需实机验收。

第二批补偿修复：管理操作失败恢复原内核后另行恢复系统代理；安装／修复已提交但内核恢复失败，明确报告已完成事实并清理候选后恢复原归属。卸载不会被伪装撤销，TUN关闭意图保存失败或子进程恢复失败分别报告。单Geo更新与恢复使用统一候选／服务暂存路径；资产变更前撤销旧manifest证明，失败恢复重新复制旧资产。旧runtime布局扫描／自动清理已移除。Windows安装防火墙失败作为结构化警告返回，不改成服务未安装，也不静默成功。

### 第六批服务日志契约（2026-11-03）

当前服务协议revision 9，应用和helper需同步发布，无旧协议读取分支。服务日志读取验证当前会话，返回服务启动身份、单调序号、最早／最新游标及至多100条原始输出（保留stderr标记、单条64KiB）。应用启动立即读窗口，之后250ms增量读取，重连不重复正文，helper重启重建游标；窗口覆盖明确提示缺口。Local仍使用私有WS／管道。连续三次失败暂停至目标变化，应用停止／会话变化取消旧请求。

## 服务维护命令

| 操作 | 当前执行 |
| --- | --- |
| 服务启动 | 无参数运行既有 daemon；Windows 接 SCM，macOS/Linux 保留 launchd/systemd 注册与停止流程 |
| 界面安装／修复 | 应用调用随包服务程序 `--prepare-install`；准备端复制所需内核、计算摘要，再把同一个服务程序复制到临时目录请求提权 |
| 提权安装 | 临时服务程序 `--install`，进入平台安装模块。停止确认、修复互斥、暂存发布、管理员批准内核、就绪回读、结构化失败及防火墙警告契约继续保留 |
| 只更新批准内核 | 同一准备入口带 `--core-only`；提权参数为 `--install --install-core ... --sha256 ...`，不携带 `--install-service`，不重建服务注册 |
| 界面卸载 | 应用把随包服务程序复制到临时目录，提权执行 `--uninstall`；先停止并确认本应用服务／归属，再删除登记和所属文件。临时副本避免 Windows 执行映像锁及 macOS 受保护用户路径问题 |
| 帮助／版本 | `--help`、`--version` 在 daemon 日志、运行时和所有权锁之前返回 |
| 无效命令 | 明确报错；拼错安装／卸载参数不会落入 daemon 启动，也不会先创建系统服务目录 |

维护分流由 `platform-service/src/maintenance/mod.rs` 持有，平台实现分别放在同目录 `install.rs`、`uninstall.rs`，共享维护操作复用 `shared.rs`。`src/bin/service.rs` 是唯一服务入口。安装准备需要的客户端能力由 `standalone` 特性包含；仅依赖客户端的 GUI 不编入 daemon 维护模块。

主程序统一从自身可执行文件同目录取得服务程序；macOS `.app/Contents/MacOS` 和 Linux AppImage 包内资源定位继续使用实际二进制目录。服务目录与应用登录自启动仍是不同所有者，不把安装服务改成打开 GUI 自启动。

本次不改 IPC revision 9、服务名、数据格式或归属，不提供旧工具入口、旧格式兼容或迁移。原独立工具源码转为内部维护模块，未维护第二套执行逻辑；未使用的旧 NSIS 服务安装资源已删除，应用交付继续由 Velopack 负责。

开发构建：`cargo build --locked --manifest-path platform-service/Cargo.toml --features standalone --bin suki-clash-service`。此命令只构建，不安装服务。2026-11-05 的隔离检查覆盖服务命令分流、错误参数及只暂存两个应用可执行文件；未执行真实提权安装／修复／卸载。
