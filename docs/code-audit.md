# 本轮代码审核

日期：2026-10-29。

范围：设置/订阅增强编辑布局、设置持久化和提交、内核启动、资源提示、HTTP/WebSocket 私有通道。未声明完成全仓逐行审核。

| 原实现 | 本轮处理 |
| --- | --- |
| 校验后的 Preferences 再转换成字符串字段并重新构造 | 直接传递已验证的 Preferences |
| DNS/嗅探提交先校验通用字段，随后再做包含同样字段的完整校验 | 删除外层重复校验，保留提交边界完整校验 |
| prepare_startup 只转发 prepare | 删除转发方法 |
| 程序设置维护路径、Weak、Mutex 注册表 | 已有生命周期执行端作为实际写入所有者，删除第二套锁表 |
| 设置保存与文件恢复 | 保留当前分组原子替换及真实失败恢复，不新增备用格式或迁移 |
| Windows 管道连接只尝试一次且仅显示 ErrorKind | 对明确的 ERROR_PIPE_BUSY 按 Tokio 文档短暂等待；其他错误直接返回，保留系统错误码 |
| 首次窗口只显示启动错误或缺失资源其中之一 | 启动错误与独立的资源警告分别显示，各自只有一个提示责任方 |

管道等待针对文档明确的正常协议状态，且现有应用会同时建立日志、连接、流量等实时连接；未为未知错误增加重试。旧日志没有 Win32 错误码，不能断言其必然为 231。

保留外部订阅、脚本、下载和文件格式的入口校验与预算。它们约束真实外部输入，不属于为假设性内部并发增加的防御分支。后续极低概率假设须先说明场景、概率和影响并取得用户确认。

183 项普通测试通过；真实 Mihomo 的规则/覆写/DNS/嗅探集成回归通过，构建及 Clippy 通过。桌面读取工具超时，原生窗口视觉未完成实机验收。Windows 完整交叉检查因缺少 MinGW 编译器中断；从生产源码提取的管道连接方法及 Windows 测试通过 Windows 目标 API 编译检查。Windows 运行行为仍需实机验证。
