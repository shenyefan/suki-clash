## 根据实际返回点区分错误

服务端依据本仓库的 `platform-service/src/core/ipc.rs::dispatch` 与 `server.rs`：

| 接口／返回点 | 状态码与含义 | 应用处理 |
| --- | --- | --- |
| IPC 请求体读取／处理预算耗尽 | 408 | 只读状态、就绪及日志观察继续退避读取，保留现有会话 |
| IPC handler 返回异常 | 500 | 同上；不能据此认定内核停止 |
| `/status` 状态采集失败 | 503 | 同上 |
| 归属、鉴权、参数或协议拒绝 | 401／409／422 等 | 保留明确的拒绝语义，不进入临时不可用重试 |
| 成功回读确认停止、Fatal、会话归属变化 | 结构化状态／错误 | 原有会话结束与清理流程 |

`is_read_unavailable` 专用于只读观察；`is_unreachable` 仍只表示传输不可达。未将 HTTP 失败扩展到启动写入重放、服务接管或维护判断。已有启动去重令牌处理维持其原本范围。

Mihomo 核对版本为官方 Meta 分支提交 `0455d0d28c4526937380505153e65a843d8612e8`，读取固定提交源码：

上述状态属于各自操作，不能统一解释为内核死亡。节点测速仅按实际的 504 及客户端等待期限分类超时，移除将服务层 408 套用到内核测速的规则；Provider／DNS 操作错误保留操作失败。WebSocket 握手移除缺少内核返回依据的 408／429 特判，4xx 保留请求拒绝语义。本次未增加通用 429／502 恢复规则。

## 配置层级和提交范围

- 可视化表单仅发送实际编辑字段，执行端串行读取最新已提交文档，再按完整路径合并。DNS 的 `fallback-filter.geoip`、`dns.ipv6` 和顶层 `ipv6` 各有独立路径；未知字段与同级其他字段保留。
- YAML 显式保存提交该原生文档，不夹带陈旧的可视化表单快照及覆写启用开关。
- TUN 补默认值不再把顶层 `ipv6` 复制到 `dns.ipv6`，不替换明确的 DNS 开关、模式及地址池。
- 全局 DNS 与嗅探均先于有序用户覆写合成，用户覆写可按保存顺序进一步定制。应用控制通道保护仍在最终阶段执行。
- Mihomo `config/config.go::UnmarshalRawConfig` 从 `DefaultRawConfig` 开始；缺少 nameserver 时使用内核默认上游。`parseDNS` 对启用 DNS 且最终上游为空报错，因此允许省略 nameserver，仍拒绝明确的 `nameserver: []`。空监听地址及空 fake-IP 地址池不再被应用提前拒绝。基础类型、非空地址格式及真实内核校验继续保留。
- 文件替换为单文件原子提交，配置／生命周期修改由同一执行端串行处理；跨文件、内核与操作系统的整体操作无法承诺全局原子性，继续使用明确提交点和失败补偿。设置 JSON 分组更新读取最新文档，恢复仅作用于所属分组。

## 编辑交互及导出

普通可视化表单（含多行列表）不提供保存按钮，文本失焦提交；YAML／脚本显式保存，操作带图标并在右下角。搜索吞字通过 GPUI Kit 0.9.1 的原生搜索修复解决。

诊断导出使用原生保存位置选择框。ZIP 保留已有配置、程序及内核日志，并通过鉴权固定接口读取当前服务自身日志尾部（最多 2 MiB），统一脱敏。接口不接受文件路径，不要求内核正在运行；读取失败在包内记录原因，其余诊断内容仍可导出。当前接口需要协议 revision 10，应用与服务须同步构建及安装，不添加旧协议兼容。
