# 服务启动与应用自启动检查（2026-11-16）

## 原因

应用的 `AutoRun` 由 `src/desktop/autostart.rs` 管理登录自启动注册。Windows 使用当前用户的计划任务；macOS/Linux 使用 auto-launch。应用启动时按持久化设置协调注册，显式修改时先修改系统登记，再提交设置，提交失败恢复登记。此开关不负责服务安装。

服务的 Windows SCM 入口和独立 daemon 入口原来都会在启动对账后调用 `restore_desired_state`。服务根据上一轮活动所有者的 `core_should_be_running` 和旧 `last_clash_config` 启动内核，不读取应用的 `AutoRun`。关机或应用异常结束未完成停止请求时，旧运行意图可一直保留。因此关闭应用登录自启动后，系统启动服务仍可能启动内核，加载上次物化的配置及其中的 TUN 设置。

## CV 对照

- 本地 `clash-verge-rev-dev/src-tauri/src/core/autostart.rs::update_launch`：`enable_auto_launch` 只控制 GUI 登录自启动登记。
- 本地 `src-tauri/src/utils/resolve/mod.rs::resolve_setup`：应用启动先初始化服务探测，再通过 `init_core_manager` 启动内核。
- 本地 `src-tauri/src/core/manager/mod.rs::init`、`manager/lifecycle.rs::start_core_inner`、`manager/state.rs::start_core_by_service_with_config`：应用发起启动，生命周期选择服务或子进程，再显式向服务发送配置。
- 本地 `src-tauri/Cargo.toml` 与仓库 `Cargo.lock` 引用服务 v2.7.7，提交 `3ed29700b093190b5e7addcaa892e77f172af544`。核对该提交的上游 `src/core/desired.rs::restore_desired_state`，它也会按旧运行意图启动内核。因此本次没有照搬该恢复策略，按 Suki 的产品要求取消跨服务进程的自动内核启动。

## 当前契约

- 服务可由 SCM、launchd 或 systemd 随系统启动，作为提权助手等待命令；应用“开机自启”继续只管理 GUI 登录登记。
- 服务进程启动仅对账：核验已记录的旧进程身份，停止确认属于旧会话的进程；PID 被复用时不终止其他进程。
- 旧进程结束后，将上一轮活动所有者的运行状态置为停止并清除活动会话。保留所有者代次计数，后续应用请求获得新代次。
- 不保留任何 `restore_desired_state` 入口或旧内核配置、日志配置快照写入。状态文件只记录运行意图、代次和时间。
- 状态接口不把已经结束的会话显示为“恢复中”；安装探测不会被其误报为内核占用。
- 状态文件损坏明确报错并保留原文件，IPC 仍可启动，内核启动门禁保持关闭。
- 手动打开应用或登录自启动打开应用，仍执行应用的启动脚本、从当前设置及订阅合成、校验、内核启动和系统代理协调。关闭登录自启动不表示手动打开应用时禁止内核启动。
- 当前服务进程内的内核崩溃重试与 IPC 监听重建继续使用既有有限预算。整个服务进程重启后不自动恢复内核；应用需要重新发起启动。
- 安装、修复、维护命令仍在 daemon 启动之前分流；应用正常退出仍显式停止自有内核。

## 验证

隔离测试覆盖无运行记录但有旧意图、PID 被其他身份占用、旧进程身份匹配后的终止、旧会话失效、新代次分配、状态与安装占用回读，以及损坏文件的保留与启动门禁。普通测试不修改真实系统服务、系统代理或路由。

Windows 验证通过：

- 服务库 87 项测试与服务维护入口 24 项测试通过，1 项既有性能测试忽略。
- 服务全部目标严格 Clippy、格式检查与差异检查通过；正式 `standalone` 服务构建通过。
- 主程序登录自启动登记协调回归测试通过，覆盖关闭、自启动协调等待与显式保存相同值。
- 使用 `standalone,test` 服务二进制、模拟内核及集成驱动，在隔离命名管道和测试状态目录中验证真实进程重启：先显式启动内核，强制结束本测试创建的服务，再重新运行服务。驱动确认服务没有活动会话、内核 PID 或运行意图，随后可重新显式启动和停止。重复启动确认不换进程，错误会话请求被拒绝，运行资产暂存与停止回读通过。
- 集成驱动同步使用当前 HTTP 错误契约检查错误会话拒绝，不再把应有的 HTTP 422 当作驱动本身失败。

本次不修改界面，不安装或替换本机服务。构建产物通过测试不代表已经运行在系统服务中。真实系统重启、用户登录、TUN/路由和 macOS/Linux 服务启动仍需平台实机验收。
