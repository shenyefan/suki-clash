## C38／C36／C06／C04／C02 与 UWP（2026-10-31）

- 服务暂存返回结构化 RestartRequired 时走校验后的受控替换，并在内核确认后提交设置；配置拒绝和普通通信错误不自动重启。失败保留旧配置，恢复失败显示失败并保留原始原因。
- 服务卸载和显式转子进程接入“管理服务”菜单；确认关闭 TUN，预校验普通内核后停止已有会话。TProxy／routing-mark 仍需服务时明确拒绝切换，不伪装普通进程成功。
- macOS 仅用户显式代理修改可申请网络设置授权；启动恢复和守卫不交互。单操作最多一次授权，失败暂停自动同步。
- Windows 自启动采用 CV 普通／管理员计划任务，interactive logon、无超时退出；失败恢复完整原任务 XML，而非仅恢复一个布尔值。
- ClashSuki 原生 UWP 方案足够，采用 FirewallAPI 枚举、保留未知豁免、服务写入和回读；增加期望集合校验避免覆盖他人并发更改。防火墙仅处理服务批准内核及已认证用户应用目录内核，固定命名，不提供任意路径执行入口。
- CV 没有另一套 TUN 路由脚本；自动路由由 Mihomo 执行。移除原生 listeners 的过度拒绝，Linux TProxy／routing-mark 走权限分支；不支持平台仍明确拒绝。

用户要求先忽略测试：本轮只进行构建、Clippy 与平台代码编译，不运行测试、不安装／卸载真实服务、不改本机网卡、代理、任务计划或防火墙。新增服务协议 revision 6，需要显式修复之前安装的服务，未做协议兼容或自动迁移。

本轮构建收尾：主程序与三个服务工具构建、主程序及服务严格 Clippy 通过；Windows 服务／网络原生 API／自启动模块和 Linux 服务代码交叉编译通过。没有运行本轮测试，也没有进行真实系统权限或网络操作。卸载／转子进程使用明确动作确认和 5 秒撤销窗口；UWP 入口按 CV 放在内核维护。
